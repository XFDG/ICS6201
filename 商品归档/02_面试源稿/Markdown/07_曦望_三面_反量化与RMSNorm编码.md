## 一、这一轮主要考什么

核心是把算子描述落实成可运行的 GPU 映射，并解释每个线程处理什么、临时结果存在哪里、归约何时完成。追问主要针对代码正确性和资源使用，而非只看是否知道某个优化名词。

1. 口述任务涉及 GPU 内存、行主序布局、按行 scale 反量化，以及 RMSNorm 相关融合实现。
2. 需要给出 C++/CUDA 接口实现，现场限制使用某些现成库；具体题面未保存在 TXT 中。
3. 怎样根据矩阵维度选择启动配置？配置怎样传入实现？
4. 一个 block 有多少线程、多少 warp？每一行由谁处理？
5. 如果列数比线程数大，单个线程负责哪些元素？

## 三、题目完整性说明

原题通过聊天或屏幕展示，TXT 没有完整数据类型、量化公式、scale 的精确定义、函数签名、误差阈值或可编译代码。因此本篇是题型复盘，不能当作原题完整重建。

练习前先写清楚：输入存储类型、反量化公式、scale 广播维度、权重是否按列、epsilon 位置、累加类型、输出类型、是否连续存储。任何缺失项都应由练习者明确假设，而非冒充原题约束。

## 四、整理补充：从正确实现走到优化

### 第一步：用最小尺寸解释索引

先用两行、少量列手写每个输入输出位置。标出一个 block 对应一行还是多行，一个线程负责一个元素还是一串元素。将逻辑列数与 `blockDim.x` 分开，避免用同一个 `block_size` 同时表示数据规模和线程数量。

### 第二步：拆清归约阶段

按“加载并反量化 → 求局部统计量 → 行内归约 → 计算归一化因子 → 写输出”画阶段图。逐项检查中间值的可见范围和同步条件；对于可能含分支的同步，确认参与线程是否一致。

### 第三步：在有基线之后减少开销

候选实验包括 warp 级归约、多 warp 汇总、减少重复加载、按输入尺寸选择映射，以及调整每线程处理的元素数。它们只是待验证方向，不能预设一定加速。比较正确性、Kernel 时间、寄存器使用和访存，不仅看代码更短。

## 五、边界用例与来源

- 列数小于一个 warp、非二次幂列数、列数超过单 block 线程数量。
- 全零输入、不同正负值、极小值、不同 scale、非对齐尾部。
- 只读输入和输出别名问题；每一行使用自己的 scale；权重维度检查。
