# 面试押题 05｜R3 Router Replay 与 RL 训推一致性

更新：2026-09-29。对应九坤实习中的“R3 Router Replay”。这里的 replay 是 **MoE 专家路由回放**，不是 CUDA Graph replay；两项技术会出现在同一 rollout 系统中，但解决的问题不同。

## 0. 开源仓库技术介绍与应用

[verl](https://github.com/verl-project/verl) 是大模型 RL 后训练框架，组织 rollout、奖励计算和训练更新；[vLLM](https://github.com/vllm-project/vllm) 负责高吞吐生成；[Megatron-LM / Megatron Core](https://github.com/NVIDIA/Megatron-LM) 提供大规模 Transformer 训练及张量、流水线、专家等并行能力。

**典型应用：**多 GPU 的大模型强化学习。一次迭代可理解为“生成 response → 计算奖励与训练所需量 → 更新策略”；生成与训练可能使用不同引擎。我的 Router Replay 集成正是连接这两个执行路径，减少离散专家选择偏差，不是替代 PPO 等优化算法。

## 1. 系统背景与个人贡献

RL 链路用 vLLM 执行 rollout，用 Megatron 执行训练，由 veRL 协调数据与执行。即使权重相同，两个引擎的算子、batch 形状、并行布局和浮点运算路径也可能不同。MoE 的 top-k 是离散选择，轻微的 Router 分数变化可能切换 expert，进而放大 hidden state 和 logprob 漂移。

我的工作是将已有 Router Replay 方法落地到内部链路：采集 rollout 的 expert ID，经数据协议传给 trainer，实现 observe/replay 入口，处理 token/layer/top-k 与 response mask 对齐，建立异常指标与 A/B/C 对照，并推进多卡运行。不能把已有方法说成我提出的新 RL 算法，也不能把这项工作说成原创上游 PR。

## 2. STAR 口述版（约 90 秒）

**S｜背景。** MoE rollout 和训练使用不同执行引擎，模型权重相同仍会有离散路由偏差，导致同一 response token 的训练侧重算 logprob 与 rollout logprob 不一致。

**T｜任务。** 我负责把 rollout 实际路由带到训练侧回放，并建立能区分“链路真的对齐”与“指标自比较”的监控和实验。

**A｜行动。** 我把每个 token、每层、top-k expert ID 按 `[T,L,K]` 采集与传输；训练侧同时保留自然路由用于观测，replay 时将 expert 选择替换为 rollout 记录，但 gating 权重和 expert 前向仍在训练侧计算。我补齐 response mask、缺失/shape/空样本检查，先过 CPU 契约测试，再跑短程 GPU smoke 和同配置 A/B/C。

**R｜结果。** 在 8×H200、Qwen3-30B-A3B BF16、GSM8K 的 20-step 实验中，未回放时自然路由不一致约 17%～19%，回放后执行路由与目标一致；fτ² 降低约 36～145×，KL 降低约 4～7×，20 step 内无 hang、engine error 或 metric error。后续 128 卡、300B 级研发模型的单轮 200-step 运行属于本人确认的内部交付记录，公开目录没有完整脱敏日志，因此不附会为公开可复核的收敛或 reward 结果。

## 3. 每个阶段到底保存、使用什么

```text
vLLM rollout
  生成 response、rollout logprob、expert IDs [T,L,K]
        ↓ 协议传输与 token/layer 对齐
Megatron logprob 重算 / observe
  保留自然 top-k；按模式回放 expert IDs；统计 response 区间 drift
        ↓
Megatron actor update
  回放离散选择；训练侧重新计算 gating/expert 前向 → backward
        ↓
权重同步，下一轮重新 rollout 与采集路由
```

route 张量的三个维度分别是 token、MoE 层、top-k 位置，值域为合法 expert ID。只保存最终 expert ID，不需要把 rollout 的全部 Router logits 当成训练侧常量复制过去。route 记录具有 `O(TLK)` 的存储和传输成本；它通常比只保存 response token ID 大很多，不能沿用旧押题中“比 response token 数据量更小”的说法。

训练侧的核心区分是：固定离散 expert 选择，不冻结可导分数和 expert 参数。对于“在选中 expert 上归一化”的常见 Router，可以示意为：

```text
I = rollout expert IDs
g_i = softmax(selected training-side logits)_i
y = Σ(i in I) g_i · Expert_i(x_train)
```

这是解释梯度的示意，不替代具体模型原有的 gating、归一化和缩放规则；实现必须保留模型原语义。expert ID 是索引，不求导，但 gating 分数和被执行 expert 的计算仍能参与反向。

## 4. 最重要的口径：自然路由与实际执行路由

| 对象 | 怎么比较 | 回放后的解释 |
|---|---|---|
| 自然路由偏差 | 训练侧未替换的 `I_train_natural` 对 rollout 的 `I_rollout` | 不承诺归零；两个引擎仍可能想选不同 expert |
| 执行路由一致性 | 实际 dispatch 的 `I_train_executed` 对 `I_rollout` | 回放正确时应一致，用于检查链路/执行 |
| 错误自比较 | 把 replay target 自己当 actual，再与自己比较 | 恒为零，不能证明真实 dispatch 或自然路由性质 |

因此简历的“17%～19% → 0”必须讲成：**baseline 自然执行时存在路由偏差，replay 后实际执行路由按目标对齐**。这不是同一自然 Router 的数学差异被消灭，也不是仅凭 route=0 就证明训练质量提高。

现存开发总结和旧押题对 mismatch 命名存在不一致。面试时使用上表明确对象，并以 logprob drift 的独立指标作为效果证据；不要背“R3 把训练侧自然路由 mismatch 降成 0”。历史报告没有完整保留两个口径的所有逐步数据，也不要编造自然 route 的 C 组新数值。

## 5. 指标、对照与验证

三个对照组：A baseline-observe、B R2-observe 都记录训练自然路由但不执行回放；C R3-replay 使用 rollout 路由。模型、数据、硬件、精度与训练设置对齐，指标只统计 response token，不让长 prompt 淹没真正关心的偏差。

| 指标 | 回答的问题 | 防止哪种误判 |
|---|---|---|
| route mismatch / top-k overlap | 专家选择是否不同，集合与顺序如何变化 | 只比集合掩盖位置/权重对应关系 |
| fτ² | 概率比偏离超过 2 倍的 response token 比例 | 均值掩盖极端尾部 |
| KL / k3_kl | 记录的 logprob 分布漂移/估计口径 | route=0 被误当成概率完全一致 |
| selected logprob absolute difference | 采样 token 的 logprob 差异幅度 | 只观察路由不观察输出 |
| metric_error、有效 token/layer 数 | 指标是否真的计算成功 | 空 mask 或缺失 route 假装“零误差” |

记录中 fτ² 的直观定义是：

```text
mean_response_tokens(max(p_train/p_rollout, p_rollout/p_train) > 2)
```

实现时优先用 logprob 差处理，避免直接概率下溢。fτ² 的“2”在这里是阈值，不应口头解释成简单平方误差；KL 指标也要遵循原记录的 estimator，不能未看实现便宣称计算了完整词表的精确 KL。

CPU 侧 18 项测试覆盖 shape、层顺序、top-k、mask、错误分支等数据契约；GPU 再检验真实 rollout/trainer 链路。CPU 单测不能替代多卡语义验证，GPU loss 正常也不能替代协议测试。

## 6. 已验证结果与证据等级

| 运行 | 已有结果 | 正确解释 |
|---|---|---|
| 8×H200、Qwen3-30B-A3B BF16、20 steps | A/B mismatch 约 17%～19%；C 执行回放对齐；fτ² 下降 36～145×，KL 下降 4～7× | 主定量证据，不是 320B 整模实验 |
| 同一 20-step | selected logprob 差下降约 2.2～2.5×；0 hang/engine error/metric error | 已测窗口的稳定性，不等于永久无故障 |
| 4 节点×8 卡、TP2、eager、5-step smoke | R2/R3 mismatch 0.2579/0；KL 0.00388/0.00089；吞吐 113.90/104.68 | 约 8.1% 吞吐开销，短程扩展验证 |
| 128 卡、内部 300B 级研发模型、1 道竞赛题单轮 200-step | 本人确认完成，接入 SwanLab，相关改动合入内部开发仓 | U 级内部终态；无公开脱敏原始日志，不外推 FULL Graph/reward/收敛 |

20-step 主数据例子：step 1 的 A/C fτ² 为 `3.38e-3/3.94e-5`，约 86×；step 15 为 `3.39e-3/2.34e-5`，约 145×；step 20 为 `3.20e-3/8.94e-5`，约 36×。36～145× 是不同 step 的范围，不是最终奖励提高倍数。

## 7. 高频问题与直接回答

### Q1：为什么同样权重也会选择不同 expert？

不同算子、batch 形状和并行归约顺序会产生低位差异；当第 k/k+1 个专家分数接近时，离散 top-k 会翻转，影响后续子网络。这里主实验使用 BF16，不能把问题全部归结成“推理 FP8、训练 BF16”。

### Q2：为什么记 expert ID，不直接复制 rollout logits？

需要约束的是执行过的离散路径。训练侧仍应按当前 hidden state 和参数计算可导 gating 和 expert 前向；复制 rollout logits 并当常量会改变训练语义，还增加数据量。索引契约比转运完整 logits 更清晰。

### Q3：固定了路由，Router 还能训练吗？

能。固定的是该批轨迹里的离散专家选择，不是 Router 参数；选中专家的权重仍由训练侧分数计算，梯度可回到分数和 expert 参数。具体可导路径服从模型原有 gating 公式，不能把所有 MoE 都简化成同一 softmax。

### Q4：回放是否只在 backward 时有作用？

不是。它先影响前向选择哪组 expert，logprob 重算阶段就能测到漂移变化；actor update 的有梯度前向同样应用回放。旧 logprob 评估通常是无梯度重算，不能把它说成必须保留计算图才能做之后的 backward；更新时会重新前向。

### Q5：训推 logprob ratio 就是 PPO 的 ratio 吗？

需要区分。此处 drift ratio 比较训练引擎重算概率与 rollout 引擎概率，用来测同权重下的系统偏差；PPO 更新还涉及当前策略和行为/旧策略的 ratio。二者在流水线中有关联，但不能把所有 logprob 字段都叫成同一个“importance ratio”。

### Q6：response mask 为什么特别重要？

关注的是 policy 生成的 response token，prompt 通常没有同样的策略评估含义；若 prompt 很长，混入分母会稀释错误。还要对齐 teacher-forcing 的位置偏移、padding、截断和 EOS；若 mask 全空，报错或单独计数，不返回伪装正常的零。

### Q7：路由都回放了，logprob 为什么还不完全一样？

相同 expert ID 不代表 attention、gating 分数、expert 算术和并行 reduction 完全相同。R3 去掉的是离散 expert 翻转这个放大器，不承诺全模型逐 bit 相同，因此仍需看 fτ²/KL/selected-logprob 指标。

### Q8：怎样避免“拿 target 跟 target 比”的自证？

分开保存 natural route、replay target 与实际 dispatch 的观测，名称和统计口径不能复用；加入缺失/错层/错序的负例，检查指标真的报错，并记录非零有效样本数。只有回放模式 route=0 不足以证明自然路由被改善。

### Q9：这个方法的代价是什么？

route 的采集、传输、存储与训练侧处理都有成本，且同一批轨迹多次更新时可能有旧路由约束。我的 32 卡 smoke 实测约 8.1% 吞吐开销，不用论文的其他数字替代本地结果，也不宣称“几乎免费”。

### Q10：128 卡扩展到底证明了什么？

本人确认的内部记录说明实现完成了更大规模的运行与监控落地，但没有公开保存脱敏逐步日志和完整 graph 配置。因此可讲工程规模，不把 8 卡的 36～145×直接搬到 128 卡，也不声称完成所有模型的收敛/最终 reward 验收。

### Q11：R3 会不会永久冻结专家选择？

不会，新的 rollout 会基于更新后的模型重新产生 route。但在某一批数据的重复更新期间，会受该批采样时路径约束；更新步数和策略漂移较大时应监测这个取舍，而不是把回放描述成无条件等价的梯度变换。

### Q12：跟 FlashInfer hang 的关系是什么？

R3 使用 vLLM rollout，vLLM 可能走 FlashInfer fused collective，因此底层 hang 会阻塞 route 产出；但 route 数据契约和 sentinel FTZ 是两个不同问题。8 卡 eager 成果与两卡 Graph 修复是不同验证记录，不能拼成所有规模 FULL Graph 已验收。

## 8. 必须守住的表述边界

- 说“执行路由对齐”，不说“自然 Router 差异被消除”。
- fτ²/KL 是一致性指标；没有最终 reward/准确率/收敛证据就不声称提高了它们。
- 128 卡 200-step 的内部终态和 8 卡公开聚合数据分开讲。
- 自己的贡献是工程实现、观测契约、排障、验证与扩展，不是已有方法或上游代码的发明权。
