## 二、九坤实习经历：两版并列

### 版本 A：系统与性能广度版（Word 文末“实习经历版本2”）

**2026.04-至今　九坤投资—至知研究院　大模型系统与高性能计算实习生**

- 面向 8xH200 上的大模型 MoE-RL 训练链路，打通 `veRL + Megatron + vLLM + DeepEP/flex` 的 R3 Router Replay 预验证；定位 vLLM CUDA Graph/compiled sampler 路径导致的 `sample_tokens` timeout，固定 eager 规避后完成 baseline/R2/R3 的 5/25/50-step 对照，全部 0 hang、`metric_error=0`。
- 设计并实现训推路由一致性诊断闭环：从 rollout 侧采集 token-layer-top-k 维度 `routed_experts`，在 Megatron 训练侧按 response mask 做 Router Replay，并上报 `topk_overlap`、`route_mismatch_rate`、`valid_token_layer_count` 等指标；多组实验达到 `topk_overlap=1.0`、`mismatch=0.0`，单步有效 token-layer 统计约 2.4M-2.7M。
- 扩展 logprob drift 对照指标，统一 baseline/R2/R3 的 `f_tau_2`、KL、`k3_kl`、`abs_diff` 口径；在脱敏实验中 R3 相比 baseline 将 `f_tau_2` 降低约 30x-46x，15-step 独立对照达到 77x 低漂移，并验证 R2“只记录不回放”基本不改善 drift。
- 面向 H200 MoE/GEMM 热路径开展 Nsight/Nsys profiling 与算子级口径对齐，修正 `T*topk` 全展开 rows 与 DeepEP compact rows（`TK_valid`）混用导致的 4x-6x 误判；基于 1,024 条 forward range 构造本地回放，三个代表 shape 与内部 profile 差异约 `+0.46%/-1.11%/-5.40%`。
- 参与 Quack/CUTLASS grouped GEMM config-level tuning，围绕 `gemm_gated`、`gemm_out` 分析 MFU、latency 与 expert 分布；通过补充 SM90 autotune 候选使目标线上 shape 获得约 `+5.3%` 加速，14 shape x 3 分布整体提升约 `+1.84%`，并确认 pure GEMM 平均 MFU 约 66.5%。

### 版本 B：三项核心成果版（当前 Word 正文）

**2026.04-至今　九坤投资—至知研究院　大模型系统与高性能计算实习生**

- **FlashInfer CUDA Graph 稳定性修复**｜针对 H200 上 vLLM TP=2 FULL CUDA Graph 的 rollout 卡死问题，构建两卡最小复现并将根因收敛到 fused AllReduce + RMSNorm 的通信轮询逻辑：原实现通过浮点比较识别 Lamport -0.0 sentinel，FTZ 会将合法 FP32 负次正规数误判为负零，导致轮询无法退出、GPU Kernel 不结束并最终触发 rollout timeout。在现用 FlashInfer 版本中将 sentinel 判断改为 0x80000000 位级精确比较后，两卡最小复现及模型级 Graph on/off 回归全部通过，重复 Graph replay 未再出现 timeout 或 hang。
- **R3 Router Replay**｜复现小米论文，针对 vLLM rollout 与 Megatron 训练侧 MoE 路由不一致问题，打通 `[token, MoE-layer, top-k]` route 采集、传输与回放链路，并建立 response-mask 对齐及异常检测，覆盖 18 项 CPU 测试；在 8×H200、Qwen3-30B-A3B BF16 的 20-step 实验中，将 route mismatch 由 17%-19% 降至 0，Ftau2 降低 36-145×、KL 降低 4-7×；最终扩展优化至 128 卡集群，使用内部 300B 模型完成竞赛题单轮 200-step 运行并接入 SwanLab 监控，结果与 8 卡情况对齐，将改动合并进开发仓。
- **OE 异步算子开发**｜将 recent-token history 与 `oe_input_ids` 构造保留在 GPU，以 Triton fused-hash 消除 GPU 同步及 H→D 回传中的 Bubble，并修复 mixed batch、请求恢复、slot reuse 与 reorder 下的跨 step 状态更新；TP1 28/28 case 通过，吞吐较 sync +4.99%、较 async-unfused +1.94%；引入 TP>1 batch-invariant 安全路径后，TP2/TP4 情况下确定性由 48.8%、75% 提升至 100%、0 mismatch，吞吐分别约 +4.6%/+3.0%。

### 可选第四条：评测链路

- **性能与能力评测链路**｜搭建 MoE/Attention 四组正交性能与数值评测，以及 UBIEval 模型能力回归链路，累计完成 140 组性能用例与 25,624 道题评测；按 Kernel/Operator/E2E 和 aggregate/逐样本/张量三个层级拆分验收，识别控制变量误归因与 MoE/Mix 数值不等价问题，避免以单一吞吐或总分替代正确性结论。
