# 6月22日-6月26日 周报

## 总体总结

本周 R3 的重点从“链路能跑通”推进到“真实 observe 口径下可验证”。6月22日完成 A/B/C v2 5-step，对三组都打开 rollout route 采集，只区分训练侧是否 replay；A baseline-observe 首次量到推理 route 与训练自然 route 约 18-19% 的 expert mismatch，C R3 replay 后 mismatch 归零，同时 `f_tau_2` 比 A 低约 70-80x。

6月23日继续完成 A/B/C observe 口径 20-step 验证。A/B 的真实 route mismatch 全程稳定在 17-19%，C 全程为 0；C 的 `f_tau_2` 比 A/B 低约 36-145x，`kl` 低约 4-7x，`selected_logprob_abs_diff_mean` 低约 2.4x，并且 20 step 全程 0 hang、0 `EngineDeadError`、0 `metric_error`。这说明当前结论已经可以表述为：R3 在 logprob-level 显著降低训推漂移，并且 replay 机制在 observe 口径下生效；但还不是最终任务效果提升结论。

6月24日到6月26日主要做工程化和阻塞排查：整理 32 卡 R2/R3 集群运行脚本与指标口径，梳理 checkpoint/停卡恢复 SOP，并把 vLLM TP=2 + FULL CUDA Graph hang 收敛到 fused AllReduce + RMSNorm 路径。当前 guard 关闭 `fuse_allreduce_rms` 的候选方案已首次通过，但 fused kernel 内部指令级证据还需要 Rev3 Nsys 和 standalone NCU 补齐。
