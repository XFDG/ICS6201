## 3. 训练算子支持

### 3.1 FA3 deterministic SWA backward：dQ semaphore 依赖链调度

**状态：A；代码与 wheel 已交付，训练框架短步 E2E 待补。**

#### Situation / Task

变长、长序列、SWA + sink 的 deterministic backward 存在显著回退。目标是在不增加 kernel、workspace 或 D2H 的前提下，解释并降低 deterministic dQ 路径的等待成本，同时保持自身逐位确定性。

#### Action

1. 用 Nsys/NCU 与因子消融拆分 dQ、dK、dV；确认 dQ semaphore 链占 deterministic 增量 99.67%，dK+dV 合计不足 0.4%。
2. 定位 reverse scheduler 与绝对 ticket 次序冲突：后继 CTA 已 resident 却在等待尚未调度的 contributor，形成 spin-wait 链。
3. 在原 fused main kernel 中改为 contributor-relative reverse ticket，并复用 LPT/SPT reverse scheduler。
4. 只使用 host 已有的 max/avg length 元数据进行长短序列分流；不新增运行时回传。
5. 对短序列和不匹配 shape 保留原生 fallback，避免局部优化引入普遍退化。

#### Result

| 指标 | Baseline | Optimized | 结果 |
|---|---:|---:|---:|
| 代表 packed trace 完整 backward | 6.755 ms | 1.699 ms | **3.98×** |
| 代表 main kernel | — | — | **5.93×** |
| Uniform 2K–12K | — | — | **1.59–5.37×** |
| 0.5K / 1K | baseline | fallback/新路 | **+0.43% / -0.51%**，基本持平 |
| 自身逐位确定性 | — | 1000 runs | **PASS** |
| 数值参考与通用回归 | — | 3601 cases | **3601/3601 PASS** |

#### 边界

- 新调度相对旧顺序可能改变 bit pattern；要求是新路径自身 bitwise deterministic，并通过 FP32 reference，不宣称与旧实现逐位相同。
- Megatron 1–5 step E2E smoke 尚未完成，不能写“训练 step 3.98×”。
- CUDA 13.1 / 新 PyTorch wheel 目前只有编译与 import 证据；由于驱动条件不匹配，不能写成 GPU 验证通过。

### 3.2 Router orth-loss compiled fusion

**状态：A/B；完整 MoE Layer 已验证，原 8-device full step 待补。**

#### Situation / Task

MoE 训练 trace 中，每层 orth-loss 重复构造 identity，并执行 normalize、margin、pointwise 与 reduction。steady forward 共 17 个 GPU operation，其中 Gram GEMM 只有 2 个，主要问题是周边碎片化。

#### Action

- 使用 `||G-I||² = ||G||² - 2·trace(G) + E` 消除 margin=0 的 identity。
- margin 路径计算全矩阵 excess 后减 diagonal excess，保持只累计 off-diagonal loss。
- 使用 `torch.compile(fullgraph=True)` 融合 normalize、margin、pointwise 与 reduction，保留 Gram GEMM。
- 新增默认关闭的 feature flag；分别评估 V1 in-place、V2 identity-free、V3 compiled。
- V1 虽单函数快，但因 `CopySlices` backward 使完整层 -3.16%，明确 NO-GO；V3 作为最终候选。

#### Result

| 指标 | Legacy | V3 Compiled | 变化 |
|---|---:|---:|---:|
| Target forward | 0.117588 ms | 0.082559 ms | **+29.79%** |
| Target forward+backward | 0.478209 ms | 0.388468 ms | **+18.77%** |
| Full MoE Layer forward+backward | 17.674392 ms | 16.973511 ms | **+3.97%** |
| Target training peak | 90.005 MiB | 80.003 MiB | **-11.11%** |
| GPU operations / steady forward | 17 | 7 | **-10** |
| Value / gradient | — | 9 cases | **9/9 PASS** |

#### 边界

- 3.97% 是 4×H200 完整 MoE Layer forward+backward，不是 full training step。
- 首次 enabled call 约有 3 秒 compile 开销，steady-state 数据不包含首次编译。
- dynamic shape、CUDA Graph 与原 8-device full step 尚未验证；开关默认关闭。

### 4.1 Batch-invariant Router GEMM 多后端自动选核

**状态：A/B；核心实现与确定性矩阵闭环，继续灰度。**

#### Situation / Task

固定 `128×128×64` persistent tile 在 decode 小 M 时存在大量无效计算，但替换 kernel 必须同时满足动态 M、batch-invariant、CUDA Graph capture/replay 与 fallback 覆盖。

#### Action

- 建立 persistent / Triton Full-K / DeepGEMM 多后端。
- Graph capture 前执行同步数值 preflight 与 Graph preflight；按完整 tensor signature 缓存后端决策。
- replay 内不动态切换；失败时 `DeepGEMM → Full-K → persistent` 回退。
- 默认 persistent，auto 通过显式开关灰度；用 path trace 验证真实选核。
- 个人 contribution 限定为 Router selector、signature/preflight/cache/fallback、构建依赖与 CI、Graph workspace 生命周期；HPC BF16 MoE 与 Sink Attention 核心 kernel 属团队能力，不记为个人开发。

| 层级/负载 | 结果 | 门禁 |

| Router microkernel | **2.949×** | 目标 shape 数值与 Graph preflight |
| 48-layer Router GEMM median | **-73.39%** | kernel 135/135；模型 20/20 bitwise |
