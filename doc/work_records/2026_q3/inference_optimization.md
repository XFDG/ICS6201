# 推理优化与 Programmatic Dependent Launch：公开工作记录

## 结论先行

本阶段完成了四类推理优化的受控评估框架：Attention 路径、MoE 路由/专家路径、Router GEMM 以及异步历史依赖算子。每类优化均采用“基线、单开关、组合开关”的正交方式，并把数值一致性、预填充和解码性能分开记录。结果表明，优化收益依赖 batch、输入长度、并行度和组合方式；不能用单一 case 代表端到端收益。

同时完成了 CUDA Programmatic Dependent Launch（PDL）的机制调研与小型验证设计。PDL 可减少相关 kernel 之间的主机端提交/同步空洞，但只适用于依赖关系明确、producer 和 consumer 协作方式可控的链路；它不是通用的 kernel 加速开关。

## 统一验证方法

1. 固定模型、精度、输入分布、并行度和预热策略，仅改变一个优化开关。
2. 对每个配置同时记录输出对比、延迟或吞吐统计，以及失败样本。
3. 按预填充与解码分别观察，并扫描多个 batch 与上下文长度，避免形状偶然性。
4. 组合优化必须重新测量；各单项收益不可相加。
5. 出现结果异常时，先验证开关是否真正生效，再讨论性能归因。

## 四类优化的工程经验

### Attention

目标是减少 attention 相关的冗余工作和调度开销。公开结论是：收益与序列形状紧密相关，短请求和长上下文的瓶颈不同；性能结果必须与精度、缓存策略和并行配置一起解读。

### MoE

目标是优化 token 路由、专家 dispatch/combine 与相关计算。评估中将 MoE 开关与其他优化拆开，并以完整矩阵确认收益区间。曾发现错误的开关组合会把不兼容路径当作“优化结果”，因此把配置解析和生效证据列为测试前置条件。

### Router GEMM

重点是为路由后的矩阵乘选择匹配形状的实现，核对 compact/非 compact 行、K 维度、精度与并行通信边界。可迁移经验是：先把实际 shape 分布与 baseline 对齐，再比较 kernel；仅在少数 shape 上的提升不能直接写成整体收益。

### 异步历史依赖算子

该路线通过在设备侧维护历史状态，减少 CPU-GPU 往返及不必要同步。验证重点不仅是吞吐，还包括多卡状态一致性、生成确定性、prefill/decode 混合阶段和 batch 变化时的语义边界。

## PDL 调研与使用判断

PDL 允许 dependent kernel 在满足依赖后由设备侧更早推进执行。建议把它作为特定热点链路的优化工具，而不是替代 CUDA Graph、流并发或算法优化。

适合优先验证的条件：

- producer/consumer 之间有稳定且可描述的依赖；
- 工作量足以掩盖协调成本；
- 正确性 oracle 能覆盖跨 kernel 数据可见性；
- profile 能区分提交空洞、等待和实际算力瓶颈。

不适合直接启用的条件：依赖图频繁变化、调用方无法控制调度边界、或当前热点主要来自访存/算法而非提交延迟。

## 证据边界与后续建议

- 公开版仅保留相对趋势和方法论，不披露专有模型、服务负载或绝对吞吐。
- 后续应先建立 shape 分层的基线报告，再为每条候选路径补充 profile 和数值回归。
- 若引入 PDL，需以“无 PDL、仅 PDL、相关替代机制、组合方案”四组对照，并在不同形状下复验。
