# 2026-06-15 至 2026-07-15 算子月度总结

时间：6-15～7.15

相关工作：

> 范围：MoE RL 训推一致性、多卡推理稳定性、OE 异步支持、算子评测与 Sparse Attention 调研。
> 核心结论：本月完成了从 RL 训练现象、两卡最小复现、GPU kernel 根因到模型能力回归的跨层验证闭环，并补齐 OE async 的功能、正确性和性能结果。

@照野

- RL 链路支持：协助 RL 团队完成 veRL R3 路由观测、baseline/R2/R3 对照和指标沉淀，20-step 中将训推 route mismatch 从 17%～19% 降至 0，`f_tau_2` 降低 36～145 倍、KL 降低约 4～7 倍。

- 稳定性修复：定位并修复 FlashInfer 0.6.4 在 vLLM TP=2 + FULL CUDA Graph 下因 FTZ 误判 Lamport sentinel 导致的 rollout hang，回移补丁和 FlashInfer 0.6.12 均通过两卡最小复现与 graph replay 回归。

- 功能与性能优化：完成 OE 算子 async scheduling 支持和 token history 正确性修复，TP1 fused-hash 在严格正确性矩阵下较同步路径提升 5.0%，TP2/TP4 的 28 组 decode 用例各重复 3 轮均 0 mismatch，吞吐分别提升约 4.6%/3.0%。

- 评测链路：搭建 MoE/Attention 四组正交性能与数值评测及 UBIEval 能力回归链路，完成 140 组性能用例和 25,624 题评测，并识别出控制变量误归因及 MoE/Mix 数值不等价问题。

- 分析调研：调研 Native Sparse Attention 的压缩、连续块选择、滑动窗口和硬件协同设计，形成覆盖训练、推理、长上下文及 CUDA Graph 的 Sparse Attention 后续验证方案。

- 未来目标：
  - 短期：完成 FlashInfer 修复的完整 RL step 验收，推动 OE async 合入并自动化性能与正确性回归。
  - 中期：搭建 H200 Sparse Attention 训练/推理原型与评测矩阵，并完成 R3 多节点长跑、收敛效果和性能开销验证。
  - 长期：建设覆盖 kernel、vLLM、模型能力和 RL 训练的统一验证与自动归因体系，支持 Sparse Attention、融合算子及新 GPU 架构迁移。
