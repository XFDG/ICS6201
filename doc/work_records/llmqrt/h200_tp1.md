# H200 TP=1 验证指南

本项目已在北京集群 NVIDIA H200（SM90、CUDA 13.0、PyTorch 2.13.0）上完成单卡 LLMQRT AWQ CUDA 推理验证。

## 已验证配置

- 模型：`Qwen2.5-0.5B-Instruct-AWQ`
- 模式：`CUDA_VISIBLE_DEVICES=0`，即 TP=1
- 后端：修复后的 LLMQRT AWQ CUDA GEMV/GEMM
- 用户原始运行：生成 64 tokens，10.27 token/s，峰值显存 0.68 GiB
- 修复后回归：模型生成 31 tokens 后主动 EOS，11.93 token/s，峰值显存 0.68 GiB
- sanitizer：原故障 shape `M=1, K=896, N=4864`，`ERROR SUMMARY: 0 errors`

## 构建

在 GPU 节点上执行：

```bash
cd /volume/pt-train/users/zhaoye/LLMQRT
source /volume/pt-train/users/zhaoye/envs/gpu-cu130/bin/activate
export CUDA_HOME=/usr/local/cuda
export PATH="$CUDA_HOME/bin:$PATH"
export TORCH_CUDA_ARCH_LIST=9.0
python setup_runtime.py build_ext --inplace
```

修改 CUDA 源后如需无条件重编译，额外加 `--force`。

## H200 修复说明

扩展以 `sm_90` 编译。原 `gemv_kernel_g128` 在输入维度不是 1024-element warp tile 的整数倍时，会先读取不存在的 scale/zero group；Qwen 的 `K=896` 只有 7 个量化 group，最后四个 lane 却读取第 8 个 group，导致 `cudaErrorIllegalAddress`。

当前修复增加尾部 group 边界保护，使用 PyTorch 当前 CUDA device/stream，并将默认 decode kernel 切换到已验证的 coalesced v2。原故障 shape 已通过 `compute-sanitizer`，端到端 CUDA 生成也已通过。

若需要排查数值或 kernel 问题，可显式切换到安全的解量化加 `torch.matmul` 路径：

```bash
LLMQRT_AWQ_BACKEND=torch bash scripts/run_h200_tp1.sh <AWQ_MODEL_PATH>
```
