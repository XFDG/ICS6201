# 通用算子公共库迁移与低开销接入

记录截至：2026-10-19；最后一次原始远端迁移状态核对为 10 月 9 日。

## 结论

本阶段将模型工程中的通用非量化算子整理到共享算子库，统一接口和维护入口。部分算子已完成库侧合入；重排与归约实现已有验证，低开销入口也已有原型，但消费侧接入与训练验收尚未全部完成。10 月 19 日的进度记录没有新增 GPU 测试。

## 分工与交付方式

库侧负责 kernel、公共接口、构建和算子测试；消费侧保留模型抽象、路由元数据、框架适配和上层调度。接入方案通过固定源码版本并分别构建两个 wheel，使依赖关系可以追踪。

迁移前先查重。同功能实现需要对齐输入、输出、精度和确定性，再决定选用或整合。完成调用切换和验收后才清理重复实现，避免库侧合入与消费侧使用版本脱节。

|---|---|---|
| QKV 归一化与旋转位置编码 | 库侧合入，补充并行支持及梯度融合 | 核对消费侧版本与调用 |

## 如何区分 kernel 开销与接口开销

迁移验证观察到大尺寸和 CUDA Graph 情况基本持平，但小尺寸 eager 组合调用存在额外成本。原型让同一动态库、同一 CUDA 函数分别经不同绑定入口调用，用于隔离 Python/框架入口成本。

原型在受测小尺寸下显著缩小了额外开销，大尺寸和 Graph 路径没有形成明确的新收益。该结果仅来自合成算子用例，不能替代完整训练吞吐，也不能视为正式安装包已经接入。

## 已有验证与正式验收缺口

原迁移记录包含多轮精度回归、相邻算子回归、memcheck/racecheck、峰值张量显存和 launch 次数对比。低开销原型还检查了 BF16 位模式、确定性、stream 与 CUDA Graph。

正式交付仍需完成：

1. 取得最新源码，避免把旧快照当作当前分支。
2. 在公共 API 中接入低开销入口，核对框架调度与注册行为。
3. 解决 Python ABI 与 PyTorch 绑定兼容性；依赖 Python 专属绑定的原型不能直接沿用原稳定 ABI wheel 标签。
4. 安装实际构建的 wheel，重新执行精度、安全性和多轮性能回归。
5. 消费侧固定依赖版本、切换调用并完成真实训练验收。

这项工作的主要产出是统一维护与可验证交付。迁移本身不预设提速，原型正确也不代表发布包兼容性已经解决。
