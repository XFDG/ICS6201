# 开发资产迁移与可恢复归档

依据 2026-10-09 至 10-10 的迁移记录整理；后续开发以上海工作副本为主。

## 已完成的历史工作

历史核心文档、补充材料和引用资料已复制到新的持久工作区，保留原有内容与相对结构。迁移记录报告了文件内容校验和 Markdown SHA256 校验，已有断链单独登记。

可重新下载的公共源码、依赖和构建缓存与原创改动分开处理。独有分支、未提交修改及新文件先保留补丁或快照，再进行历史清理；归档保留恢复说明、来源版本与校验记录。

## 为什么只备份文档不够

文档可能引用 CSV、图片、trace 和外部相对路径；移动 Markdown 不会自动移动这些证据。工作树还可能依赖另一个目录中的共享 Git 对象，复制文件本身也不能保证 Git 关联仍有效。

因此验收需要分别检查文件内容、引用关系与 Git 关联。原记录明确保留了部分关联失效状态及恢复办法，没有把“文件已保留”写成“所有工作树立即可运行”。

## 本次同步边界

历史迁移是一次性快照，之后两地编辑不会自动同步。当前公开工作记录通过上海仓库的 `me` 分支维护；内部原始材料与公开摘要属于不同产物，不进行无差别上传。

此文介绍历史迁移方法，本次没有重新执行存储清理、重建开发环境或远程验证北京副本。内部容量、目录拓扑、账号及备份位置不纳入公开稿。
