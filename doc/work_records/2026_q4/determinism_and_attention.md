# 确定性路径审核与 Attention 性能复测

来源时间：2026-09-18、2026-10-12；整理日期：2026-10-19。

## 最新结论

开启确定性标志不能直接当作逐位可重复认证。最新复测对全部输出和梯度做重复校验，仍发现部分受测 Attention 路径不一致。这个结论仅针对记录中的安装包和测试输入，不能推广到所有 FlashAttention 版本。

早期性能表存在配置和输入不对齐问题，已撤销其模型对齐结论。新版重新审核并行配置、本地专家数、梯度累加、输出头实现、Q/K/V 布局和路由关系，再进行单算子比较。

## 配置与输入审核

合成参考数据流串联 embedding、归一化、QKV、位置编码、attention、路由、专家计算、输出头及交叉熵。每个单测的 OFF/ON 共用输入、权重和合成上游梯度；重排与专家计算共享路由关系。

输入覆盖不同长度、变长打包和偏斜路由。偏斜分布是人为压力用例，不是线上分布；输入也不是 checkpoint 捕获的真实激活。单算子时间不能相加当作训练步时间，跨 rank 通信、优化器与重叠调度没有形成完整覆盖。

## 测量和正确性是两个检查

- 计时使用预热、多轮交替 OFF/ON 和轮均值的中位数；哈希、首次编译和 profiler 不计入主时间。
- 同时观察 CUDA Event 区间和设备事件总和；前者可能包含 eager 发射间隙，两者不能混用。
- 重复性比较覆盖完整输出与梯度，包括独立累加的主梯度；跨模式数值误差另行报告。
- 未锁定时钟的微小差异需要结合原始轮次波动判断。

复测显示确定性成本随算子与输入变化，路由和归约路径可能出现明显成本，某些重排路径也可能变快。因此不把开关成本概括为统一比例，也不用单个热点的相对涨幅代替全模型影响。

## 版本与调用路径核对

审核从框架标志开始，逐层追踪模块构造、后端选择、参数传递与实际安装包。所查 Transformer Engine Attention 模块在构造阶段读取确定性状态，候选 Attention 后端收到对应参数；这不意味着 Linear、GroupedLinear 和 RMSNorm 都因同一个标志切换 kernel。

源码中存在目标实现，也不能证明执行环境已经加载它。尤其是参考分支与安装包版本未证明一致时，只能分别报告源码分析和实测结果，不能拼成一条已验证的因果链。

## Attention 排障记录

较早的 trace 分析发现了一类优化失效：已有滑窗反向优化的 dispatch 条件只覆盖有限头数组合，新配置未命中而回退旧路径。后续方向是按算法与 tile 的真实能力界定条件，并补充边界回归。原记录的预估收益属于待验证项。

同时识别了输出梯度清零、精度转换往返、布局复制和组件回退带来的额外成本。对应的验证原则是：

1. 在取消清零前，用 poison-buffer 和边界输入证明后续 kernel 完整覆写，不把局部观察外推到所有路径。
2. 在消除转换前核对数值语义，避免为减少 copy 改变需要的累加精度。
3. 在融合归一化与位置编码前，先修复依赖缺失和回退路径，重新测量可获得的增量收益。

本阶段完成了定位、口径纠正和受控复测；未将这些建议统一表述为已实现的端到端加速。
