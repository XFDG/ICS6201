# 智元机器人 AI Infra 一面：指标与系统边界

> 技术面复盘 · 确定性反向 / 通算重叠 / MoE / Router GEMM / CUDA Graph。基于转写改写；公司与轮次沿用来源文件标注。

## 一、这一轮主要考什么

面试会在算子、模型和系统三个层次来回核对：你是否理解算子的上层语义、怎样测到异常、指标能否自洽、改动是否具有明确适用范围。职责边界可以说明，但不能代替对接口和结果的理解。

## 二、源记录中可确认的提问

1. 怎样从全局 trace 定位到反向中的具体 Kernel？
2. 与协作方各承担哪些 profiling 和验证工作？怎样组成闭环？
3. 为什么某个实现需要严格确定性？不能把所有训练都归为同一要求。
4. SWA 与全注意力的计算范围和反向依赖有何不同？
5. dQ、dK、dV 之间怎样组织，为什么只改其中一条路径？
6. 优化前后前向、反向和整网耗时分别是多少，比例从何而来？
7. 项目中的算子缩写具体代表什么，处在模型的哪个位置？
8. 通信与 GEMM 重叠时为什么出现拖慢，实际改的是哪个配置？
9. 调参结果对哪些 shape、卡数和负载有效？是否仍有长尾？
10. CTA、block、cluster 和 SM 分别指什么？
11. MoE 的 Router 怎样选择专家，Router GEMM 在其中做什么？
12. 失败的融合尝试为什么失败，能否提供资源或数据流证据？
13. CUDA Graph 的作用和约束是什么？发生 capture 问题时怎样排查？
14. 动态选择后端与兜底逻辑如何设计，分别由什么条件触发？
15. Graph 相关 hang 怎样收敛到具体算子与状态判断？

## 三、整理补充：回答最容易失去清晰度的位置

### 先解释对象，再解释优化

把内部缩写换成一般计算含义，写清输入输出和所在模型位置。准备一个脱敏数据流图，使听者在不了解内部代码命名时，也能理解哪段是 Attention、哪段是专家计算、哪段发生通信。

### 让所有指标共用一张表

分列前向、反向、单层和整步时间；每项标注测量环境、单位、是否包括同步和通信。没有直接测量的数据就明确缺失，不从“我没有改这个部分”推导“这个部分完全没有影响”。原记录的性能数字口径不稳定，本篇不将其复用为宣传收益。

### 区分相邻但不同的概念

复习时分别画线程组织层级与硬件执行单元，避免将 CTA、cluster、SM 混为一类。将图执行的提交机制、编译优化和算子融合分开说明；不能因为 Graph 开关改变了行为，就说 CUDA Graph 本身一定完成了融合替换。

## 四、验证练习

- 对一个优化制作“修改对象 / 适用条件 / 依据 / 回归 / 限制”五列表。
- 将通信独立、计算独立、二者重叠三种执行画在同一时间轴，比较总完成时间。
- 选择一个失败方案，用输入、资源、执行路径解释其失败，而非只说“融合不行”。
- 抽查一项项目指标，确保可以从原始测量重新算出结果。
