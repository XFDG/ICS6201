## 技术基础校准

1. **线程组织与硬件单元分别描述。** thread block（CTA）、warp、thread 属于程序组织层级；SM 是硬件执行单元；cluster 又有独立语义。普通 shared memory 的协作边界是 block，不能笼统说所有 block 都可直接共用。复习时以目标硬件和编程模型为准。[NVIDIA CUDA 编程模型](https://docs.nvidia.com/cuda/cuda-programming-guide/01-introduction/programming-model.html)
2. **确定性不等于高精度，也不等于跨实现逐位相同。**浮点运算的顺序会影响结果；数学等价的操作在不同实现、平台或批处理方式中也可能得到不同位结果。需要分别定义参考精度、容差与重复运行要求。[PyTorch 数值精度说明](https://docs.pytorch.org/docs/2.15/notes/numerical_accuracy.html)
3. **图执行与融合需要区分。** CUDA Graph 表达工作及依赖，支持实例化与重复启动；具体框架或编译器是否做算子融合、替换到哪种后端，应单独查对应执行路径，不能自动归因于 Graph。[NVIDIA CUDA Graphs](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/cuda-graphs.html)
4. **FlashAttention 的原始主线是 IO-aware exact attention。**原论文用 tiling 减少 HBM 与片上存储之间的读写；不能把它概括成任意情况下减少所有算术工作。面试中的推导仍需自己补齐。[FlashAttention 原论文](https://arxiv.org/abs/2205.14135)
5. **平台插件不只是注册模型名。** vLLM 文档区分 general plugin 和 platform plugin；新硬件适配还涉及平台、worker、通信、Attention 后端和算子等。接口需对照实际使用版本。[vLLM 插件体系](https://docs.vllm.ai/en/latest/design/plugin_system/)
